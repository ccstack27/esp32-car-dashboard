# ESP32-S3 Car Dashboard

MicroPython (v1.27) web dashboard on an ESP32-S3 that switches car loads through a relay module. The ESP32 runs a Wi-Fi access point, serves a glassmorphism web UI, and can update itself over the air from GitHub. Progress history lives in `LOG.md` — add a dated entry at the end of each session.

**This repo is public.** Never commit secrets: AP password, update PIN and signing key live only in `device/config.py` (gitignored).

## Hardware
- Board on **COM18**, 16 MB flash, no PSRAM (PSRAM errors in the boot log are harmless).
- Relays are **active-high** (`ACTIVE_LOW = False` in `app.py`).
- Pin map: IO4 ignition (toggle), IO5 crank (3 s pulse), IO6 horn/alarm (hold), IO7 park light (toggle), IO15–IO18 AUX 1–4 (toggles, future use).
- Wi-Fi AP SSID `Misyubibi Lancer` (password in `device/config.py`), dashboard at http://192.168.4.1 (`/#dash` skips the intro).

## Layout
- USB-only core (never replaced over the air, so recovery always works):
  - `device/boot.py` → `recovery.on_boot()`: finishes or rolls back a pending update.
  - `device/main.py` → launcher: imports `app`, rolls back + resets if a freshly updated app crashes.
  - `device/recovery.py` → swap/rollback/confirm with `/ota/state`, `/ota/old`, `/ota/new` on the board.
  - `device/config.py` → secrets and settings (gitignored; template in `config.example.py`).
- OTA-updatable (listed in `OTA_FILES` in `tools/release.py`):
  - `device/app.py` — AP, asyncio HTTP server, relay logic, `/api/*`.
  - `device/updater.py` — Wi-Fi join (credentials in RAM only, asked every time), HTTPS download, verification.
  - `device/www/index.html` (gzipped into `release/index.html.gz`), `intro.mp4`, `bg.jpg`.
- `release/` — generated by `tools/release.py`: `manifest.json` (version, sha256 per file) + `manifest.sig` (HMAC-SHA256 with `UPDATE_KEY`).

## Update security model
- The board accepts a release only if `manifest.sig` matches its `UPDATE_KEY`; each file must match its sha256. TLS cert checking is off on purpose (authenticity comes from the HMAC).
- Update API needs `UPDATE_PIN` (5 wrong tries → 60 s lock) and ignition off; relays are switched off and controls locked (HTTP 423) while installing.
- A new release gets one boot: `app.py` calls `recovery.confirm()` after 20 s; an unconfirmed reboot or crash rolls back.

## Workflows
- **USB deploy:** `py -I tools/deploy.py COM18` (full, ~2–3 min) or `--no-media` (skip video/jpg). Also clears any pending OTA state. **Do not use mpremote** — opening COM18 toggles DTR/RTS and resets the board; `deploy.py` opens it with DTR/RTS low and speaks raw REPL. Its `Board` class works for ad-hoc on-device scripts.
- **OTA release:** edit code → `py tools/release.py <version>` → `git add -A && git commit && git push` → dashboard "Update Firmware". GitHub raw files can be cached ~5 min after a push.
- `.gitattributes` sets `* -text` so files are stored byte-for-byte (hashes must match what GitHub serves).
- Python is `py` (not `python`); run tools with `py -I`. ffmpeg via `imageio_ffmpeg.get_ffmpeg_exe()`.

## Safety rules (keep these)
- All relays OFF at boot and on shutdown.
- Crank timing enforced on the ESP32, requires ignition on, cancelled when ignition turns off.
- Horn auto-releases if the client stops sending keep-alives (700 ms).
- Don't switch relays during testing unless the user confirms the car isn't connected; on-device tests should use read-only endpoints.

## Testing tips
- UI preview: mock API server over a copy of `device/www`, screenshot with headless Edge using `--force-prefers-reduced-motion`, and strip the `.rise` animation in the copy (headless freezes CSS animations mid-way).
- On-device: raw-REPL soft reset (Ctrl-D) skips `main.py`; then `import app`, start `app.handle` with `asyncio.start_server`, and hit it over 127.0.0.1. Wrap every TLS/stream await in `asyncio.wait_for`.
